## 4. Host MoE banks — `--moe-bank-ram` (the fork's biggest subsystem; ~4,000 lines, well-tested)

Docs `docs/bank-ram.md` (633). Commits: `ea334f1` (mapping + locked prefix), `1245a15` (**one bank file for every layer**, restart reads no expert tensor, `ft bank pack`), `c359391` (kernels give back what pack stored; checkpoints say where their experts are), `6ce9d9e` (`HostBank.release` must punch pages), `9a74e19`, `5721be5` (WSL2 pin budget; never write a bank where it cannot go), `c9f75d7`/`5db600c` (`auto`, `--moe-bank-readahead`), `7d8838b` (`--moe-bank-prefetch`), `a6c834e` (`--moe-bank-rewarm`), `ad3f44f`+`00659ea`+`3c25196` (prefill reads), `37f741e`, `379bddd`, `b1c17f0`, `7744cf1`, `121d714`, `494c00e`…

- **Design**: the bank keeps its `[num_experts, …]` shape (so `OffloadMoeCache` and the prefill whole-layer streamer are untouched); the *file* does the tiering. Rows are reordered per layer so hot experts come first; `[0,hot)` = `mlock` + `cudaHostRegister`; `[hot, num_experts)` = read-only file pages, fault in, dropped under pressure, no writeback. Routing ids renumbered **in the layer before anything reads them** (`moe/bank_disk.py:136 permutation_tensor`, `:145 apply_permutation`, applied `layers/moe.py:296`).
- **File format** (`moe/bank_file.py`, 692): `MAGIC b"FTMB"`, `VERSION = 2`, `ALIGN = 4096`, `BANK_FILE_NAME = "bank.ftmb"` (`:56-59`); `_PREAMBLE <4sIQ` + 4096-aligned JSON header, then **two manifest slots** `<4sIQQ32s>` = (`FTMS`, seq, body len, **sha256(body)**) + 64 KiB spare (`:62-69`, `data_offset = slot_offset + 2*slot_bytes`), then blocks laid out **layer-major × bank**: `offset_of(bank, layer)`, each block `align_up(num_experts * row_bytes)` (`MappedBankLayout:101-172`, `block_bytes:142`, `range_of:162`, `layer_bytes:170`). Manifest holds per-layer `order` + per-block digest (`_largest_manifest:136`). Layer is *visible* only after blocks are written+synced and the manifest names it; interrupted reorders journal to `bank.ftmb.journal.L<n>` (`_JOURNAL_MAGIC FTMJ`, `:64-66`) and the next start finishes or rolls back. Fencing: `file_lock:257`, `_pwrite_all:302`, `_drop_cache:322`, `free_bytes:676`.
- **What is *not* in it** (this is the part to copy): `hot` is re-solved from `--moe-bank-ram` every start; the layer split is not stored (every MoE layer in one file, indexed model-wide; a rank maps only its own) ⇒ **new budget or new `--pp-layers` rewrites nothing**. Tied to the checkpoint by a fingerprint of expert tensor names/dtypes/shapes + shard size/mtime, and the kernel id (`nvfp4/triton`, `mxfp4/triton_gptoss`).
- **Pin accounting — cannot be double-spent**: resident rows must be *registered* or the GPU's fetch is an illegal access inside the decode graph. Form is chosen at startup by **probing with one page of the bank file itself** (not by reading `cudaDevAttrHostRegisterReadOnlySupported`, which is 1 under WSL2 and **0 on native Ubuntu 24.04/615.71.09**): shared read-only mapping, else `MAP_PRIVATE` writable + **one byte written per page then restored** to force CoW out of page cache + `posix_fadvise(DONTNEED)` block-by-block so the two copies never coexist (`mapped_bank.py:281 _pick_map_mode`, `:342 _cow`, `:405 _settle`, `:395 _touch`; `FREETOKEN_BANK_MAP=shared|private|auto`). `prefix_pinned_rows` is one number per layer ⇒ **a partially registered bank is treated as fully unregistered** with a warning naming the block count (`:378 fully_registered`); `FREETOKEN_BANK_REGISTER=none` requests that state (it still serves; every miss to CPU executor, VRAM slot cache unused). Decode safety: a miss past the prefix is handed **expert 0** before `ensure_experts_hybrid`, overwritten to `-1` after (the CPU partial's own signal); raw ids still feed the histogram. Prefill: registered half on the copy stream, remainder through pinned staging. `RLIMIT_MEMLOCK` is per-process and systemd's `MAX(64M, RAM/8)` silently halves the resident set → the startup line reports what *was* locked.
- **`--moe-bank-ram auto`** (`moe/disk_probe.py:473 AutoBankRam`, `:508 auto_bank_ram`): `MemAvailable − 4.5 GiB/rank (`NONBANK_PER_RANK_BYTES:443`) − max(2 GiB, 5 % MemTotal page-cache margin (`:448-449`))`, then **capped by the WSL2 pin budget = 40 % MemTotal − 2 GiB** (`:458-462 pin_budget_bytes`). Measured: 2060 host, 23.5 GiB RAM — RAM alone chose 15.6 GiB of Ornith's 16.9, **141/240 blocks registered and boot died**; capped it chose 7.4 GiB and started with 3.4 GiB of the predicted 4.5.
- **Prefill reads of cold rows** (`moe/bank_reader.py:60 DirectRangeReader`, `:167 BankReader`): default **buffered, multi-thread, through the page cache** (`FREETOKEN_BANK_PREAD=buffered`, threads 8, 16 MiB pieces, `FREETOKEN_BANK_PREAD_CACHED=0.9` = a piece ≥90 % cached is copied from the mapping instead; `3c25196`), `direct` = `O_DIRECT` (`ad3f44f`), `0` = fault through the mapping. Numbers: 2060/Ornith @6G held to 13 GiB, prefill **204 → 304 tok/s** buffered, **325** O_DIRECT, and **28 → 230** with readahead off; 3060s/Flash-Next **310 → 410** buffered, **440** O_DIRECT but decode **15.9 → 13.2** (a prefill stole the rows decode needed). Root cause documented: reading layer *n* evicts layer *n−1*, so each chunk re-reads nearly all non-resident rows.
- **Readahead is the single biggest lever** (worth **2.5×**): `read_ahead_kb` 8192→**256** took Flash-Next 5.9→15.0 tok/s; gpt-oss-120b optimum **2048** = 16.4. Recommendation formula `widest_row_block/√24 → nearest power of two` (`disk_probe.py:385 recommend_readahead_kb`, table `bank_disk.py:215 _WIDEST_ROW_BLOCK_BYTES`; widest block 1600 kB Flash-Next, 7.91 MiB gpt-oss). `--moe-bank-readahead auto|N` writes sysfs before each rank maps (`mapped_bank.py:827 _apply_readahead`), off by default, device-wide, not restored.
- **Rewarm** (`moe/bank_rewarm.py:46`, `mapped_bank.py:478 cold_residency`/`:501 rewarm`): after N s idle, `mincore` the rank's own mapping; <95 % → re-read in file order, 64 MiB steps, stop at step boundary on arrival; if a pass ends *less* cached than it began, back off ×4 up to 10 min. Also pages **the process's own swap** back (`moe/swap_back.py:99 SelfSwap`, `process_madvise`/`MADV_POPULATE_READ=22`, `/proc/self/pagemap` `_PM_SWAPPED`, `FREETOKEN_REWARM_SWAP=0`). TTFT after forced page-cache loss, short prompt: 2060 **30.9 → 3.1 s** (warm 1.0); 3060s **16.2 → 5.8 s** (warm 3.0).
- **Prefetch** (`--moe-bank-prefetch`): CPU executor reads the routing **before waking workers**, `mincore` then **`madvise(MADV_WILLNEED)` per distinct cold row** — gate/up before the workers, down right after (`cpu_executor.py:344 enable_bank_prefetch`, `:373 bank_prefetch_stats`, `:360 bank_prefetch_supported`; kernels `kernel/csrc/cpu_moe/cpu_moe_ext.cpp` `prefetch_phase`/`prefetch_only`). Measured off/on/off/on, 2000 tok: 3060s @64 GB-equiv **TTFT 9.1 → 5.2 s, 23.9 → 25.7 tok/s, p99 220 → 188 ms**; on a host with RAM to spare it got **slower** (33.4 → 29.8) because exact-row advice gives up the neighbour rows readahead would have kept → **off by default**.
- **`ft bank pack`** (`moe/bank_pack.py:421`, 952 lines; `bank pack/verify/unpack/reorder/info` CLI `moe/bank_cli.py`): drops by **bytes, not names** (`lossless_roles:253`) — NVFP4 codes+block scales reproduce, per-tensor global scales stay in the checkpoint; MXFP4 blocks/scales/biases go; never-read tensors stay. Double-checks every layer, SHA-256 per layer+role, rewrites mixed shards, **hard-links** expert-free ones, moves `bank.ftmb` in, records `freetoken_bank_pack.json` (original shard headers + index + whole-file SHA-256) ⇒ reversible via `unpack`. **The bank becomes the only copy of the experts.** Disk table: first start 16.9 GiB/74 s; reorder 19 layers = 16 GiB written/123 s; pack 3 shards/4.9 GiB/129 s/3.7 GiB peak RSS; `verify` 42 s. `pack`/`verify` ran on Ornith (same temperature-0 text); **`unpack` only on synthetic checkpoints** (host drive filled); nothing run on Flash-Next/gpt-oss.
- **Measured**: Flash-Next 128 GB pinned **18-20 tok/s, prefill 6 s/chunk** → 64 GB `--moe-bank-ram 48G` **14-15 tok/s, 10-45 s/chunk**; gpt-oss-120b one 3060 64 GB **15.2**, 32 GB **4.5**. 77 % residency covers **87.5 %** of out-of-sample routes (vs arbitrary slice +10 pts); steady state ~3 % of routes reach disk. Always measure ≥2000 tokens (110 tokens read 11.5, 2360 read 15.0). Every "64 GB" row is a **locked balloon on a 128 GB / DDR5-4000 4-DIMM host** — a real 2-DIMM 64 GB machine has *faster* memory and has never been tested.
- **Documented self-traps to not inherit**: (a) `is_cpu_layer` was checked **before** the hybrid branch ⇒ declaring mapped banks locked + listing every layer CPU-side **skipped a 1,180-slot VRAM cache (worth 40 %)**, invisible in logs; (b) `--moe-bank-ram` must **disable** `--moe-cpu-layers auto` (`engine.py:2925` comment; `9a74e19`, gpt-oss 12.50 → 14.59 tok/s); (c) the initial "madvise at startup is worth 3-4×" theory was **false** — `smaps` showed `Rss == Size` (33,269,760 kB, 144 VMAs) and it was still 8 tok/s, i.e. the disk-bound case had never been reproduced on a 110 GiB host; (d) `--spec-mtp` appends its bank layer **after** the placement is solved ⇒ `expert_perm` and `layer_residency` must grow together.

## 8. Prefill preservation — `--prefill-chunk-budget`, `--prefill-mixer-pieces`, `--prefill-profile`, `--pp-*`

- **Why**: the chunk is the unit of *transient* VRAM; linear-attention kernels allocate ∝ chunk per chunk. RTX 2060, one 30,448-token prompt: chunk 8192 (upstream default) = **0.97 GiB** transient → **1081 s** and sometimes `CUDA driver error: device not ready`; 4096 = 0.49 GiB → **232 s**; 1792 = 0.21 GiB → 249 s. Measured transient **124.5 KiB/token** (Ornith) — **GDN 116.5**, full-attention 79.8, MoE 16.7 KiB/token; Flash-Next @pp 270.0 → 195.7 with pieces.
- **Budget** (`server/args.py:890`, `engine/config.py:48` default **0.55**): measure once at startup (one 1024-token forward, never a downward probe of the configured size), then **re-solve per prefill** against `free + (reserved − allocated)`; log first + moves ≥256; `0` = old behaviour; out-of-`(0,1]` ignored.
